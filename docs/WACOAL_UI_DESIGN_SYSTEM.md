# 華歌爾 UI 設計規範 V1 — 可跨專案複用

## 原則
此文件為樣式與易用性基準，不能覆蓋各專案的已核准 UI 規格、數據契約、表單欄位、保存邏輯或營運計算規則。以「主管看得懂、店櫃手機好操作、報告能列印」為核心。

## 設計語言
- 主色：#163247 深藍；輔色：#176d8c；底色：#f3f6f8；卡片：#ffffff；分隔線：#dce4e9。
- 正向 #2d8068；警示 #e89a27；負向 #c95a4a。數據與狀態加文字說明，不只依賴顏色。
- 使用 Noto Sans TC／台灣系統字體；內文 14–16px；重要數字 tabular-nums；萬元、件、%、百分點有正確單位與小數位。
- 卡片圓角 12–18px、低強度陰影、8px 間距節奏；選單明確、對齊一致，避免整頁充滿不必要卡片。
- 表格：桌機可高密度呈現；手機優先顯示重點欄位，再展開次要細節，禁止把缺資料顯示成 0。
- 報告／列印：乾淨的 A4 版面、明確層級、文字與圖表可獨立理解；保存已核准的特定 Word/PDF 版型，不強制替換。

## 依專案適配
- 排班系統：週／月視圖清楚、排班時段/人員/異動提示可讀，手機點選目標 >=44px；不得改變班別和 Firestore 儲存方式。
- 指導員與月報：清楚的填寫與審核狀態、編輯／輸出動作，以及去年/今年報表可追溯；不得改動數據欄位或匯出語義。
- 業績儀表板：實績、目標、達成、去年對比、缺口優先；計算口徑和品牌配對不可更動。

## 每次 UI 開發
先讀既有程式與已凍結規範 → 選 1–3 個符合需求的方案 → 預覽（有工具才宣稱已預覽）→ 在獨立分支做前端變更 → 檢查 390/768/1440 → lint/build/驗收 → 獨立發布審核。
不得因「美觀」增加多餘動畫、外部資料傳輸或替換技術架構。
